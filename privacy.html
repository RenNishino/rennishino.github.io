Privacy policy

For life, a personal single-user tool. Last updated 1 September 2026.

life is used by one person: me, its author. It has no other users, no sign-up, and no server. It runs entirely on my own computer. This policy describes what Google user data it touches and what happens to that data, so that it can be stated plainly rather than assumed.

1. What data is accessed

ScopeWhat is read
.../auth/calendar Events from the Google Calendars I own: title, start and end time, location, and colour label. Used to list today's schedule and to total hours per colour over the previous seven days. Write access is included so that I can create events from the command line. One of these calendars is shared with my spouse, so events she has created on it are read too; she is a joint owner of that calendar and is aware of this. Calendars I merely subscribe to and do not own (public holidays and similar) are excluded.
.../auth/gmail.metadata Used by the scheduled morning job. For unread messages from the last two days only: the From, Subject and Date headers, the message ID, and labels. Message bodies are not accessible under this scope at all.
.../auth/gmail.readonly Used only when I explicitly ask for help triaging specific messages: the body of those messages, so that I can decide whether each one needs a reply or can be deleted. The scheduled job does not use this scope, and message bodies are never written to any file.
.../auth/gmail.modify Used only to carry out tidying actions on my own mailbox that I have explicitly approved: marking messages read, starring them, adding or removing labels, archiving, and moving messages to Trash. This scope cannot delete anything permanently — items moved to Trash remain recoverable for 30 days. The broader https://mail.google.com/ scope, which does permit permanent deletion, is deliberately never requested.

Mail is never sent without my say-so. A reply is shown to me in full first, and is only sent after I have explicitly approved that individual message. Nothing is ever sent automatically or in bulk.

No other Google service, product or scope is used.

2. What is stored, and where

  • OAuth tokens — stored as files in ~/.config/life/ on my Mac, readable only by my user account. They are never transmitted anywhere except to Google's own token endpoint in order to refresh them.
  • The daily briefing — a Markdown file containing today's event titles and the subject lines of unread mail. These files are kept in a private Git repository which is mirrored to a private repository on GitHub. The repository is not public and is not shared with anyone.
  • Nothing else is retained. There is no database, no cache, no log of API responses, and no copy on any server I operate.

3. Who the data is shared with

It is not sold, rented, or disclosed to anyone. There are no analytics, no advertising, no third-party trackers, and no other users to share it with.

Two disclosures, for completeness:

  • GitHub hosts the private repository described above, and therefore stores the briefing files containing event titles and email subject lines.
  • An AI coding assistant runs locally on the same machine and can read the briefing files, and — when I ask it to help triage a specific message — the body of that message. In those cases the text is sent to the model provider that serves the assistant. This only happens for messages I select, and only when I initiate it. Nothing is sent automatically, and the scheduled morning job does not contact any AI service at all.

4. Retention and deletion

  • Briefing files are kept for as long as I find them useful and can be deleted by deleting the files.
  • Access can be withdrawn at any time at myaccount.google.com/permissions, which immediately invalidates the tokens.
  • Deleting the folder ~/.config/life/ removes every stored credential.

5. Limited use

This application's use of information received from Google APIs adheres to the Google API Services User Data Policy, including its Limited Use requirements. Google user data is used solely to produce the personal daily briefing described above. It is not used to train any machine-learning model, not used for advertising, and not transferred to anyone except as stated in section 3.

6. Changes

If what the tool does changes, this page is updated and the date at the top changes with it.
